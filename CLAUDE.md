# Рай — сайт ритуальной службы (Нижний Новгород)

Сайт частного ритуального агентства «Рай». Главная задача сайта — чтобы человек в тяжёлый момент за несколько секунд понял, что делать, и связался с агентом. Тон — спокойный, бережный, без давления.

Отвечай и пиши комментарии в коде **на русском**.

## Стек

- **Astro**, только статическая сборка (`output: 'static'`). Никакого SSR и Node на сервере.
- **CSS** — обычный CSS с переменными из `src/styles/tokens.css`. Без Tailwind, без CSS-in-JS, без UI-библиотек.
- **JS** — чистый JS (или Alpine.js, если логика разрастётся). Без React, Vue и Svelte.
- **Маска телефона** — IMask.
- **Форма** — `public/api/lead.php` (PHP 8.1+): Telegram Bot API + письмо через Yandex SMTP (PHPMailer), по желанию запись в MySQL.
- **Хостинг** — shared (Reg.ru / nichost): Apache + PHP, заливка по SSH (rsync) или FTP.

## Правила вёрстки (обязательно)

1. **Только токены.** Любой цвет, отступ, радиус, тень — через `var(--…)` из `tokens.css`. Если нужного значения нет — не выдумывай, спроси. Числа в px допустимы только для размеров иконок, бордеров (1px, 1.5px) и max-width текстовых блоков.
2. **Только стили текста из спецификации.** 19 стилей «Рай/…» (+ мобильные «Рай/Mobile/…») → классы в `base.css` (`.h1 .h2 .h3 .h4 .h5 .quote .num-l .num-xl .eyebrow .num-step .title .body-l .body-l-strong .body-m .body-s .body-s-strong .label-m .label-s`). Не задавай font-size в секциях.
3. **Акцент в заголовке** — `<em>`: `<h2 class="h2">Те же похороны — <em>другое отношение</em></h2>`. Стиль `em` в заголовках: italic, цвет `--color-accent-primary`; внутри тёмных секций (`.section--dark`) — `--color-accent-soft`.
4. **Сетка:** контейнер 1200px, поля `--space-page-x`; секция `padding-block: var(--space-112)`; шапка секции → контент `--space-48`; надзаголовок → H2 `--space-16`.
5. **Семантика:** один `<h1>` (в Hero), у каждой секции `<section id="…" aria-labelledby="…">` и свой `<h2>`. Кнопки — `<button>`, переходы — `<a>`. Телефоны — `<a href="tel:+79867680944">`.
6. **Доступность:** видимый `:focus-visible`, контраст AA, у вкладок `role="tablist"/"tab"/"tabpanel"` + управление стрелками, у аккордеонов `<details>/<summary>` или `aria-expanded`. Учитывай `prefers-reduced-motion`.
7. **Адаптив:** есть два макета — desktop 1440 и mobile 375 (см. таблицу). Верстай mobile-first: база — мобильный макет, с 1024 px — десктопная сетка, между 768 и 1023 — промежуточное решение (обычно 2 колонки там, где на десктопе 3). Мобильные размеры шрифтов — стили «Рай/Mobile/…», переход к десктопным — через `clamp()`. Отличия мобильной версии (аккордеоны, шторки, бегущая лента фактов, переключатели) описаны в `rai-handoff.md`, раздел 5a — там же про скрытые слои с раскрытыми состояниями.
8. **Никаких внешних ресурсов**: шрифты, иконки, скрипты — локально (единственное исключение — Яндекс Метрика и SmartCaptcha). Google Fonts не подключать.
9. **Изображения:** `astro:assets` (`<Image>`), форматы webp/avif, `loading="lazy"` везде, кроме первого экрана.
10. Цены, телефон, адрес — **не хардкодить в разметке**: брать из `src/data/prices.json` и `src/data/site.json`.

- **Hero:** вкладки «Дома / В больнице / В другом городе» меняют три шага справа.
- **Services:** 4 вкладки меняют панель (таймлайн + карточка с ценой).
- **Pricing:** переключатель «Захоронение / Кремация» меняет цены в 3 карточках (данные — `prices.json`).
- **Agents:** клик по имени меняет карточку агента.
- **Calculator:** выбор услуги, гроба, опций, числа гостей пересчитывает итог; итог = сумма − пособие на погребение (9 678 ₽, значение `benefit` из `prices.json`, индексируется 1 февраля). Ступени и цены — только из данных. Кнопка «Зафиксировать смету» открывает форму заявки с приложенной сметой.
- **Benefits, Faq:** аккордеоны, в FAQ открыт первый пункт.
- **Calculator (mobile):** поля «Что нужно», «Гроб», «Дополнительно» открывают шторку снизу (`<dialog>`), см. `rai-handoff.md` 5a.
- **Contact:** выбор способа связи (сегменты «Звонок / Telegram / MAX»), маска `+7 (___) ___-__-__`, чекбокс согласия обязателен, отправка через `fetch('/api/lead.php')`, состояния: отправка / успех / ошибка (при ошибке показать телефон).

## Форма: `public/api/lead.php`

- Принимает POST (JSON): `name`, `phone`, `channel` (call|telegram|max), `source` (какая форма), `estimate` (смета из калькулятора, опционально), `consent`, `website` (honeypot), `captcha_token`.
- Проверки: honeypot пуст, `consent === true`, телефон — 11 цифр, SmartCaptcha (серверная проверка токена), ограничение частоты (не больше 3 заявок с IP за 10 минут).
- Отправка: сначала **Telegram** (`sendMessage`, HTML-разметка), затем **почта** через PHPMailer, Yandex SMTP (smtp.yandex.ru:465, SSL). Если Telegram не ответил — письмо всё равно уходит.
- Ответ: `{"ok": true}` или `{"ok": false, "error": "…"}` с корректным HTTP-кодом.
- **Секреты** (токен бота, chat_id, SMTP-пароль, ключ капчи) — в `config.php` **вне публичной папки** (на уровень выше `public_html`), в репозиторий не коммитить; в репо — `config.example.php`.
- PHPMailer — положить в `public/api/vendor/` (на хостинге может не быть Composer).
- `.htaccess` в `api/`: запрет листинга, запрет доступа ко всему, кроме `lead.php`.

## Аналитика

Яндекс Метрика. Цели: `call_click` (клик по tel:), `lead_sent`, `calc_used`, `messenger_click`, `guide_open`. Счётчик подключать только в production.

## Юридическое (152-ФЗ)

- Чекбокс согласия на обработку ПДн обязателен в каждой форме, ссылка на согласие и на политику.
- Страницы `/privacy` и `/consent` должны существовать.
- Баннер о cookie/Метрике — короткий, внизу, не перекрывает телефон.

## Деплой

`deploy.sh`: `npm run build` → `rsync -avz --delete dist/ user@host:~/site/public_html/` (исключить `config.php`). На хостинге: HTTPS (acme.sh), редирект http→https и www→без www в `.htaccess`, gzip/brotli, кэш для `/fonts/` и `/_astro/` на год.

## Чего не делать

- Не добавлять фреймворки и библиотеки сверх перечисленных без согласования.

- Не использовать давящие приёмы: таймеры, всплывающие окна при входе, «осталось 2 места».
- Не вставлять стоковые фото людей в горе.
